# 04. 운영 가이드 (관리자용)

개발자 없이 규칙을 고치고 사이트를 운영하는 방법입니다. 1~3단계는 처음 한 번만 하면 됩니다.

## 0. 에이전트에게 맡기기
이 가이드의 대부분은 Claude Code의 `tax-schedule-ops` 에이전트가 대신합니다. 정의는 `.claude/agents/tax-schedule-ops.md`에 있습니다. 이 폴더에서 Claude에게 평소 말투로 부탁하면 됩니다.

> tax-schedule-ops로 부가세 예정고지(4월) 기한을 4월 30일로 바꿔줘. 2027-01-01 시행이야.
> tax-schedule-ops로 정기 점검해줘.
> tax-schedule-ops로 배포해줘. 올리는 것까지 승인할게.

| 가이드 단계 | 에이전트가 하는 일 | 사람이 하는 일 |
|---|---|---|
| 1. 시트 만들기 | 드라이브에 시트 파일 3개 생성(승인 시) | 승인 |
| 2. 웹에 게시 | 단계별 안내 작성 | 게시 클릭, 주소 3개 전달 (커넥터로는 게시 불가) |
| 3. 주소 넣기 | config.js 수정 + 연결 확인 | 없음 |
| 4. 배포 | 점검 → zip 묶기 → (토큰 있으면) Netlify 업로드 → 배포본 확인 | 승인, 처음 한 번 토큰 설정 |
| 5·6. 규칙 변경 | 기본 데이터 모드: 직접 수정. 시트 모드: 셀 단위 수정 지시표 작성 + 수정 후 검증. 변경 이력 기록 | 시트 모드일 때 지시표대로 셀 수정 |
| 8. 점검 | 테스트·검수·시트 연결·기준일 확인 | 없음 |

에이전트는 세법 내용을 스스로 만들지 않습니다. 바뀐 내용, 시행일, 대상 규칙이 분명하지 않으면 고치지 않고 질문을 돌려줍니다.

### 사람이 직접 돌릴 수 있는 명령
점검(테스트 + 규칙 검수 + 조합별 건수)은 프로젝트 맨 위 폴더에서 이렇게 실행합니다.

```bash
osascript -l JavaScript scripts/check.js
```

개원일과 과목을 정해 일정 전체를 보고 싶으면 옵션을 붙입니다.

```bash
osascript -l JavaScript scripts/check.js --open 2026-11-02 --dept 피부과
```

배포용 zip 묶기:

```bash
scripts/deploy.sh package
```

## 1. 구글 시트 만들기 (처음 한 번)
에이전트에게 맡기면 탭 3개짜리 파일 1개 대신 **시트 파일 3개**(`세무일정_규칙`, `세무일정_진료과목`, `세무일정_설정`)로 만듭니다. 사이트는 어느 쪽이든 똑같이 동작합니다. 직접 만든다면:

1. 구글 드라이브에서 새 스프레드시트를 만들고 탭 3개의 이름을 `규칙`, `진료과목`, `설정`으로 바꿉니다.
2. 검수 화면(`review.html`) 맨 아래에서 `규칙.csv`, `진료과목.csv`, `설정.csv`를 내려받습니다.
3. 탭마다 **파일 > 가져오기 > 업로드**를 고르고 **현재 시트 바꾸기**를 선택합니다.
   - **"텍스트를 숫자, 날짜, 수식으로 변환"은 꼭 끄세요.** 켜 두면 `03-10` 같은 기한값이 날짜로 바뀝니다. 바뀌어도 대부분 읽어 내지만, 텍스트로 두는 편이 안전합니다.
   - 첫 줄(머리글)과 열 순서는 바꾸지 마세요. 열 이름이 바뀌면 검수 화면에 빨간 오류가 뜹니다.

## 2. 시트를 웹에 게시하기 (처음 한 번)
1. **파일 > 공유 > 웹에 게시**를 엽니다.
2. 탭에서 `규칙`을 고르고, 형식은 **쉼표로 구분된 값(.csv)**을 골라 **게시**합니다. 나온 주소를 복사해 둡니다.
3. `진료과목`, `설정` 탭도 같은 방법으로 주소를 받습니다(주소 3개).
4. 게시해도 공개되는 것은 규칙뿐입니다. 고객 정보는 원래 시트에 없습니다.

## 3. 사이트에 시트 주소 넣기 (처음 한 번)
`site/js/config.js`를 열어 따옴표 안에 주소 3개를 붙여 넣습니다.

```
rules: 'https://docs.google.com/spreadsheets/d/e/.../pub?gid=0&single=true&output=csv',
```

검수 화면 위쪽 상태 줄이 **규칙: 구글 시트**로 바뀌면 연결된 것입니다.

## 4. 배포하기
`site` 폴더 전체를 무료 정적 호스팅에 올립니다(Netlify, GitHub Pages, Cloudflare Pages 중 하나. 서비스에 따라 무료 계정이 필요할 수 있습니다).
- 고객에게 보낼 주소: `https://(받은 주소)/`
- 관리자 검수 주소: `https://(받은 주소)/review.html` (고객에게 보내지 마세요. 검색에는 나오지 않게 설정해 두었습니다.)
- 엔진 테스트: `https://(받은 주소)/tests/engine.test.html` ("전부 통과"가 나와야 합니다)

**GitHub Pages (현재 사용 중)**
- 주소: `https://pepitachoi.github.io/clinic_tax/`
- 처음 한 번: 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 고릅니다.
- 이후에는 `main`에 push하면 `.github/workflows/pages.yml`이 `site` 폴더만 자동으로 올립니다(1~2분). 저장소 Actions 탭에서 진행 상황을 볼 수 있습니다.
- 올리기 전 `scripts/deploy.sh package`로 점검하고, 올린 뒤 `scripts/deploy.sh verify https://pepitachoi.github.io/clinic_tax/`로 확인합니다.

**Netlify 자동 배포를 쓰려면 (처음 한 번)**
1. Netlify에 사이트를 한 번 만듭니다(예: Netlify Drop으로 zip 업로드).
2. 사이트 설정에서 Site ID를, 사용자 설정 > Applications에서 개인 액세스 토큰을 받습니다.
3. 두 값을 **본인 터미널**의 셸 설정 파일(`~/.zshrc`)에 `export NETLIFY_AUTH_TOKEN=...`, `export NETLIFY_SITE_ID=...`로 직접 넣습니다.
4. 토큰은 Claude에게 채팅으로 알려 주지 마세요. 에이전트는 이 환경변수가 있을 때만 `scripts/deploy.sh netlify --yes`로 올립니다.

배포는 처음 한 번만 하면 됩니다. 이후 규칙 수정은 시트에서만 합니다. `config.js`나 화면을 바꿨을 때만 다시 올리면 됩니다.

## 5. 세법이 바뀌었을 때
1. 옛 규칙 줄의 `적용종료일`에 마지막 날짜를 적습니다(예: `2026-12-31`).
2. 새 줄을 추가하고 `id`를 새로 붙인 뒤 `적용시작일`에 시행일을 적습니다(예: `2027-01-01`).
3. 옛 줄은 지우지 마세요. 시행일 전후 일정이 자동으로 맞게 나오고 이력도 남습니다.
4. `설정` 탭의 `규칙기준일`을 오늘 날짜로 바꿉니다(고객 화면 맨 아래에 표시됨).
5. 검수 화면에서 **시트 다시 읽기**를 누르고 확인합니다.

구글의 게시 주소는 캐시 때문에 **반영까지 최대 5분 정도** 걸릴 수 있습니다.

## 6. 자주 하는 작업
| 하고 싶은 일 | 방법 |
|---|---|
| 일정 잠시 끄기 | `사용`을 `N`으로 |
| 문구 고치기 | `한줄설명`, `상세설명` 수정 |
| 검수 완료 표시 | `상태`를 `확정`으로. 모든 규칙이 확정되면 고객 화면의 "검수 전" 안내가 사라집니다 |
| 특정 과목만 적용 | `조건_과목`에 `피부과,성형외과`처럼 쉼표로. 과목명은 `진료과목` 탭과 똑같아야 합니다 |
| 과목 추가 | `진료과목` 탭에 한 줄 추가. `미용기본값`은 그 과목을 고르면 "미용 시술" 답을 미리 골라 둘 값입니다 |
| 연락처·면책 문구 | `설정` 탭 |
| 일정에 연락처 붙이기 | `설정` 탭 `연락처항목`에 규칙 id를 쉼표로(기본 `PREP_CONSULT`). 그 일정을 펼치면 세무법인 전화번호가 나옵니다. 값을 비우면 어느 일정에도 안 붙고, 줄이 아예 없으면 `PREP_CONSULT`에만 붙습니다 |

## 7. 기한유형 빠른 참고
| 기한유형 | 기한값 예 | 뜻 |
|---|---|---|
| 매년 | `05-31`, `02-말일` | 매년 그 날 |
| 매월 | `10`, `말일` | 매달 그 날 |
| 개원일+일 | `20` | 개원일부터 20일 뒤 한 번 |
| 개원월말+개월 | `3` | 개원한 달 말일부터 3개월 뒤 말일 한 번 |
| 개원전 | `30` | 개원 30일 전 한 번 |

보조 칸:
- `시작연차`: 개원 연도를 1년차로 셉니다. `2`면 개원 다음 해 일정부터 나옵니다(예: 종소세, 중간예납).
- `시작개월`: `1`이면 개원 다음 달부터 나옵니다(예: 원천세).

## 8. 문제가 생기면
- 검수 화면 맨 위의 **빨간 상자**에 몇 행이 왜 잘못됐는지 나옵니다. 오류가 있는 줄은 고객 화면에 나오지 않습니다.
- 시트를 읽지 못하면 고객 화면은 마지막으로 읽어 둔 사본(그것도 없으면 기본 데이터)으로 보여 주고, "최신 일정표를 불러오지 못했어요" 안내를 띄웁니다.
