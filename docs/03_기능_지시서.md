# 03. 기능 지시서

각 기능은 "무엇을 / 어떻게 동작 / 끝났다고 보는 기준" 순서로 적는다.

## F1. 입력 받기 (S1)
- 개원일(날짜), 진료과목(드롭다운, 진료과목 표에서 읽음), 미용 Y/N, 직원 Y/N을 받는다.
- 개원일은 오늘 기준 과거 1년 ~ 미래 1년만 허용한다(범위 밖이면 안내 문구 표시).
- **완료 기준**: 4개 다 채워야 버튼이 활성화된다. 입력값을 서버로 보내지 않는다.

## F2. 일정 생성 (규칙 엔진)
1. 규칙 표에서 `사용=Y`인 줄만 가져온다.
2. 조건 칸(미용/직원/과목)이 입력과 맞거나 `*`인 줄만 남긴다.
3. 기한유형에 따라 날짜를 만든다(02 문서 2절). `매월`·`매년`은 기간 안의 모든 날짜를 만든다.
4. `시작연차`, `적용시작일/종료일`로 거른다.
5. 표시 기간(시작=개원월 1일, 끝=개원월과 이번 달 중 늦은 달부터 세어 12번째 달의 말일) 안의 것만 날짜순으로 정렬해 월별로 묶는다.
6. 날짜는 법정 기한 그대로 둔다. 주말·공휴일로 미루지 않고 화면 안내 문구로 대신한다.
- **완료 기준**: 같은 입력이면 항상 같은 결과. 검수 화면(A2)과 결과 화면(S2)이 같은 엔진을 쓴다.

## F3. 결과 보여주기 (S2, S3)
- 월별 묶음, 항목마다 날짜·이름·한줄설명·조건 태그를 보여준다. 누르면 상세설명과 근거가 펼쳐진다.
- 지금 달 강조, 지난 날짜 흐림, 하단에 "주말·공휴일이면 다음 영업일" 안내와 면책·연락처·규칙기준일을 둔다.
- **완료 기준**: 360px 폭에서 가로 스크롤이 없다. 글자 16px 이상.

## F4. 규칙 편집 (A1) — 최우선 기능
- 추천: **구글 시트**에 02 문서 형식으로 규칙을 두고, 페이지가 열릴 때 시트를 읽는다.
  - 장점: 관리자가 이미 아는 도구, 수정 이력 자동 보관, 로그인은 구글 계정이 대신해 준다. 서버와 DB가 없다.
  - 단점: 시트 공개 설정이 필요하다(규칙만 공개, 고객 정보는 원래 없음). 반영까지 몇 분 걸릴 수 있다.
- 대안: 관리자 화면+비밀번호(서버 필요), 규칙 파일을 GitHub에서 직접 수정(개발자 도구에 익숙해야 함).
- **완료 기준**: 관리자가 시트에서 한 줄을 고치면 새로고침 후 결과에 반영된다. 시트를 읽지 못하면 "일정을 불러오지 못했어요" 안내와 함께 마지막 정상본을 보여준다.

## F5. 검수 (A2)
- 기준 개원일과 과목을 고르면 미용×직원 4가지 조합 표를 보여준다. 칸을 누르면 그 조합의 S2 미리보기가 열린다.
- 규칙 오류(빈 필수 칸, 형식 오류, 중복 id)를 맨 위에 보여준다. `예시(검수 전)` 상태인 규칙은 따로 표시한다.
- **완료 기준**: 관리자가 시트를 고치고 A2를 새로고침하면 바뀐 결과를 바로 확인할 수 있다.

## F6. 개인정보 없음 보장
- 입력값은 브라우저 메모리에만 둔다. 서버 전송, 분석 도구, 쿠키 저장을 하지 않는다.
- **완료 기준**: 네트워크 요청이 페이지 파일과 규칙 시트 읽기뿐이다.

## 하지 않는 것
로그인, 알림, 세액 계산, 고객 정보 저장, 결과 PDF/캘린더 내보내기(나중에 검토할 후보).
